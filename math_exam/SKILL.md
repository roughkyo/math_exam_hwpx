# math_exam

패키지 1.3-public.1 — 2026-10-11 본문 직접 편집 및 배포 검증 업데이트. 일반 텍스트 문단과 인라인 한글 수식을 분리하고 실제 수식 치수로 배치한다. 원고와 결과물의 수식 내용·순서, 본문과 인라인 위치, 치수 측정 대상을 함께 검사한다.

원문 변환은 내용과 구조를 보존한다. 새 문항 출제는 같은 평가 요소를 다루는 새 문제를 만든다. 응용·변형 문항 요청의 기본 결과물은 **HWPX**다. 채팅 문제만 제시하고 끝내지 않는다. 양파고 한글 스킬이 없어도 이 폴더의 양식과 스크립트로 진행한다.

## 시작과 작업 경로

이 파일이 있는 폴더를 패키지 루트로 삼는다. 모든 자원은 그 폴더 기준 상대 경로로 찾고 현재 작업 폴더는 사용자의 자료 폴더로 유지한다. `C:/Users/...` 같은 다른 컴퓨터 경로를 넣지 않는다. 에이전트의 실행 도구로 Python을 호출하고, 특정 MCP·계정·API 키를 요구하지 않는다.

1. 요청이 변환/통합/수정인지 새 출제인지 구분하고, 파일·문항 수·난도·교과 범위를 확인한다. 이미 정해진 사항을 다시 묻지 않는다. 입력이 없어 원문을 구할 때는 출처와 학년도를 확인한다.
2. 원본 보존, 편집 가능한 본문·수식, 원문/정답 검증, 최종 지면 확인을 성공 기준으로 설명한다. 사용자 승인 요구는 현재 대화와 작업 폴더 규칙에 따른다.
3. `scripts/doctor.py`로 환경을 확인한다. 사용자가 준 HWPX 양식이 최우선이며, 없으면 `assets/forms/default_exam.hwpx`의 중립 양식을 쓴다. 이 공개본에는 사용자 제공 원본 양식이나 제3자 기출 문항이 포함되지 않는다. 다른 양식은 [양식·원고 규격](references/layout.md)을 읽고 adapter를 작성한다.
4. 작업 폴더의 `work/YYYY-MM-DD-math_exam-작업명/`에 원고·크롭·검증 자료를 모으고 최종 결과만 작업 폴더에 날짜를 붙여 저장한다. 원본과 기존 결과물을 덮어쓰지 않는다. 완료 후 자신이 만든 중간 자료만 범위를 확인하여 승인된 방식으로 정리한다. 삭제가 차단되면 우회하지 않고 남은 위치를 알린다.

## 원문 변환·통합·오류 수정

[변환 절차](references/conversion.md)를 읽는다. PDF 지면과 글자 좌표를 먼저 추출한다. 수식은 원본 이미지와 맞춰 한글 수식 스크립트로 작성한다. 자동 판독값은 초안이며 정확성의 증거가 아니다. 여러 학년도는 검토된 페이지들을 한 원고의 `pages`에 순서대로 합친다. 학년도·과목·문항 번호·배점·선택지·정답 대응 관계를 별도로 기록한다.

- 원본 줄을 넘어 수식을 합치지 않는다. 분수·지수·첨자는 해당 행의 수식 내부 구조로 판단한다. 조건별 함수는 하나의 논리적 블록으로 관리하되 행별 기준선과 열 좌표를 유지한다.
- 수식 사이 본문 쉼표·괄호·접속어는 본문에 그대로 둔다. `A, B`를 `AB`로 만들지 않는다.
- 본문과 수식은 그림으로 대체하지 않는다. 본문은 보통 문단의 `hp:run/hp:t`, 수식은 `hp:equation/hp:script`로 만든다. 고정 지면은 테두리 없는 표 셀의 일반 문단을 사용할 수 있다. 본문 전체를 수식 또는 조각난 그리기 글상자로 만들지 않는다. 한 문장 안의 수식은 글자처럼 놓아 뒤 조사가 수식 폭에 따라 함께 이동하게 한다. 그림은 선택·이동·크기 조절 가능한 이미지 개체이며 곡선의 모든 획이 한글 벡터 개체로 편집되는 것은 아니다.
- 원본 그림·표·프레임·구분선·문항 순서·배점·홀수형·저작권·확인 사항을 지킨다. 수식 표기와 본문까지 들어 있는 전체 페이지 이미지 위에 편집 개체를 겹치는 방식은 허용하지 않는다.
- 수정된 문구는 최종 출력본에서 다시 읽는다. 검증 기록에 썼다는 이유로 완료 처리하지 않는다.
- 원본 수식의 `LEFT ( ... RIGHT )`를 보통 괄호로 바꾸지 않는다. 검토한 원본 스크립트는 `source_script`로 보존하고 `build_exam.py`와 `validate_exam.py --plan`으로 괄호 명령 유실을 차단한다. 분수·합·극한을 감싼 큰 괄호는 `stretch_parentheses_required:true`를 설정한다. 원본 스크립트가 없으면 원문 확대 대조로 결정하며 자동 검사가 판독을 대신하지 않는다.
- 홀수형은 양식의 홀·짝 머리말 테두리 상자에 넣는다. 본문에 일반 글자로 추가하지 않는다. 머리말 좌표의 기준은 본문과 다를 수 있으므로 실제 PDF 위치를 확인한다. 굵게 바꾼 제목의 줄바꿈과 자동 쪽번호 글꼴도 확인한다.
- 바닥글은 충분한 글상자 폭, 원본 색상, 한 줄 출력을 함께 확인한다. 단순히 글자가 모두 존재한다고 통과시키지 않는다. 본문과 수식 사이 간격은 실제 글자의 끝 좌표로 확인한다. 내장 함수명 `sin x`, `cos x`, `tan theta`, `ln 2`, `log _{5} 3`을 사용한다. 함수명 및 쉼표 뒤에 일괄적으로 `~`를 추가하지 않는다. 조건부확률 세로선은 원문과 대조하여 해당 기호의 간격만 조정한다.

## 응용·변형 문항·주제 기반 출제

[출제 절차](references/authoring.md)를 읽는다. 원문 또는 주제의 평가 요소를 파악하고, 조건·함수 관계·묻는 값·풀이 과정 중 필요한 것을 바꿔 새 문항을 설계한다. 숫자만 바꾸거나 원본 그림을 그대로 붙여 새 그림이라고 보고하지 않는다.

문항 조건으로 해가 존재하는지, 정답이 유일한지, 선택지 중 정답이 하나인지 독립적으로 검산한다. 그래프는 조건과 같은 함수·교점·구간으로 새로 그린다. 표기 글자와 수식은 이미지에 굽지 않고 HWPX 개체로 올린다. `draw_graph.py`는 다항식 그래프용이며 기하·통계 그림은 별도의 정확한 좌표 도구로 만든다. 사용자에게 질문만 주어진 경우에도 필요한 그림과 HWPX까지 완성한다. 정답·해설은 문제지와 구분된 쪽 또는 별도 파일로 제공한다.

`examples/area-three.json`은 정적분 새 문항 3개와 해설의 실행 가능한 예다. 특정 예제 함수로 모든 주제를 제한하지 않는다.

## 본문과 수식을 분리하는 필수 기준

- `(X가 0 또는 1의 값을 가지는 경우)` 같은 문장에서 X만 수식으로, 나머지 괄호·한글·띄어쓰기는 보통 텍스트로 쓴다. 한글 조건 전체를 수식에 넣으면 빌더가 거부한다.
- 본문과 수식이 이어지는 문장은 `paragraph`와 `runs`를 사용한다. `text`와 `equation`을 따로 지정하고 본문 쉼표·조사·공백을 text에 둔다.
- 인라인 수식은 스크립트만 바꾸고 이전 폭을 재사용하지 않는다. `measure_equations.py`로 같은 글꼴·크기의 수식 폭/높이/기준선을 측정한 새 원고를 만든다. 한글이 없으면 이미 검증된 치수를 사용하고 실제 출력 미검증을 명시한다.
- 측정 원고에는 `measurement`의 스크립트·크기·글꼴 일치 기록이 필요하다. 수식이나 글꼴·크기를 바꾸면 다시 측정한다. 이 기록을 손으로 꾸며 빌더 검사를 통과시키지 않는다. 측정과 생성에는 같은 지수·첨자 정규화 규칙이 적용된다.
- 텍스트 수정 시험은 결과물 복사본에서 일반 본문을 찾아 보통 글자 입력으로 바꾼 뒤, 모든 수식 스크립트가 그대로인지 확인한다. PDF에서 글자가 보이거나 HWPX에 hp:t가 있다는 것만으로 직접 편집 시험을 대신하지 않는다.
- `흰 공 1개`, 문항 번호, 배점은 일반 본문이다. 수식의 sin/cos/ln/log는 내장 함수명으로 쓴다. 큰 괄호 LEFT/RIGHT와 cases 정렬을 간격 수정의 부수 효과로 없애지 않는다.

## 제작과 검증

스크립트를 처음 쓸 때 `--help`를 확인한다. [양식·원고 규격](references/layout.md)을 따라 원고 JSON을 만든 뒤 실행한다.

```text
python scripts/measure_equations.py <원고.json> <work/측정원고.json>
python scripts/build_exam.py <work/측정원고.json> <work/새문제지.hwpx>
python scripts/validate_exam.py <문제지.hwpx> <새검증폴더>
python scripts/render_hancom.py <문제지.hwpx> <work/새출력.pdf>
python scripts/validate_exam.py <문제지.hwpx> <새조판검증폴더> --plan <work/측정원고.json> --output-pdf <출력.pdf> --layout-spec <조판검사.json>
python scripts/test_layout_guards.py
python scripts/test_native_paragraphs.py --work <새검증폴더>
python scripts/test_release.py <새배포검증폴더>
```

위 경로는 설명용이다. 실제 호출은 패키지의 절대 경로와 사용자 작업 폴더의 출력 경로를 사용한다. 사용자 양식은 `--template <양식.hwpx>`를 지정한다. 기본 양식의 원본 문항 번호를 임의로 다른 양식에 적용하지 않는다.

[수식·지면 검증](references/verification.md)에 따라 내용 검증, 구조 검증, 실제 한글 렌더링, 수식별 영상 비교와 낮은 점수의 육안 확인을 수행한다. 배점 개수만 맞는다고 내용이 정확하다고 판단하지 않는다. 한글이 없는 환경에서도 HWPX 조립·구조 검사는 가능하지만 실제 출력 검증 완료로 표시하지 않는다.

`--plan`에는 실제 생성에 사용한 측정 원고를 지정한다. 수식 개수만 비교하지 않고 스크립트 내용과 순서, 본문과 수식의 문단 내 위치, 인라인 치수를 대조한다. PDF 영상 비교에서 낮은 점수가 남으면 종료 코드 2이며 육안 검토 대기 상태다. 자동 검사 성공을 시각 검증 완료로 바꾸지 않는다. 최종 ZIP은 새 경로에 풀어 회귀 검사하고, 설치 별칭 적용 후에도 manifest 해시를 확인한다.

완료 보고에는 HWPX·확인용 PDF·검증 기록 링크와 생성/수정 파일 목록을 제공한다. 원문과의 대조 범위, 실제 확인한 것, 미확인한 것을 분명히 쓴다. 오류가 없다는 보증이나 모든 디바이스에서 픽셀 단위 동일하다는 보증은 하지 않는다.
